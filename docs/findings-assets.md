### 待机取到了**骑乘**那一版动作(2026-08-09)

实机反馈里的四条,根因是同一个:「波波拉/阿米亚特整只歪在中轴左侧,一点动作就瞬移到中间,
做完又瞬移回去」「加尔/黑化加尔/雷鸣小子整只偏下,黑化加尔更多」「绅士鸡待机时看不见
手里那把羽毛剑,实机是右手斜向下指剑」。

**逻辑动作名撞车了,而撞了之后是先到先得。** 动画资产带场景类别前缀(`World_Idle`
大世界、`Common_Anger` 通用、`Fight_Idle` 战斗、`Ride_Idle` **被骑乘**…),配置表里的
逻辑名只有 `Idle`,所以比对时把前缀剥掉。剥完 `World_Idle` 与 `Ride_Idle` 就一样了,
而原来是 `TryAdd` —— 谁先被 pak 枚举到算谁的,枚举顺序恰好把 `Ride_*` 排在 `World_*` 前面。

**骑乘动作是照着骑手的挂点摆的**,整只宠物按坐骑的位置偏出去半个身位。量出来
(glb 里根关节直接子节点的平移减绑定姿势,单位米):

| 形态 | 待机取到的那版偏移 | 用户看到的 |
|---|---|---|
| 阿米亚特 | X −0.75 | 整只在中轴左边 |
| 波波拉 | X −0.78 | 同上 |
| 加尔 | X −0.28,Y −0.50 | 整只偏下 |
| 黑化加尔 | X −0.29,Y −0.76 | 偏得更多 ✓ |
| 雷鸣小子 | X −0.37,Y −0.62 | 整只偏下 |

而 `Happy`/`Anger`/`Show` 这些只有 `Common_*` 一版、没得撞,所以它们是正的 ——
「点一下动作就瞬移到中间、做完弹回去」正是这么来的。绅士鸡那条是同一个原因的另一面:
`Ride_Idle` 里它两手扶着坐骑,剑收在身后;取到 `World_Idle` 就是实机那个右手斜向下指剑的站姿。

**新增 `--probe-anim` 把撞名摊开看**(`ALL` 是全库普查)。桌宠白名单里真会撞的只有三个,
每个都是 `Ride_*` 对 `World_*`:

    idle      Ride×252  World×252
    run       Ride×265  World×265
    jumpfall  Ride×141  World×141

其余撞名(flygliding / flyhover / swim* / movel / mover / hit2)都不在白名单里。
改法是给类别前缀定优先级(`AnimNames.Rank`):**World > Common > Scene > Battle > Fight >
Ride**,没有已知前缀的垫底。桌宠演的就是「跟在身边的宠物」,大世界那一版最贴切;
战斗/骑乘/演出那几档都是**摆在别的东西旁边**的动作,位置不以自己为原点。

**换版对照**(全库重导,逐形态比 glb 里同一段动作的整只位置):103 个形态的
Idle(44)/Run(34)/JumpFall(71)动了,最大的一条是灵狐二阶 —— 它的 `Ride_Jump_Fall`
把整只推到 **X = −59.8 公里**(骑乘动画里的垃圾数据),拖放松手后那只会直接飞出屏幕;
`World_Jump_Fall` 是干净的。顺带,`Run` 的 root motion 也回来了(骑乘版本原地不动,
被判成 `in_place`、`speed_cm_s = 0`)。`sweep.py` 一位不动:失败 0 / 空白 0 / 过曝 3。

### 动作音效是**另一层声音**,不是叫声的重复(2026-08-09)

原来包里每个形态只有四段声音(开心/受惊/召唤/放松),而解包数据里躺着的远不止这些。
`dataconfig_audio.bytes` 用 `strings` 直接抽,得 27243 条 `Pet_*` 事件名,按前缀分:

| 前缀 | 事件数 | bnk 数 | 是什么 |
| --- | --- | --- | --- |
| `Pet_Action_<拼音>` | 12339 | 650 | **动作音效**:身体动静(落地、扑翅、拖尾巴) |
| `Pet_Vo_<拼音>` | 12213 | 621 | 叫声 |
| `Pet_Skill` / `Pet_Ride` / `Pet_Eco` / `Pet_Boss` … | 2700 | — | 技能/坐骑/生态/首领,桌宠用不上 |

两族库对**同一批情绪后缀**各有一套(`Common_Happy/Shock/Fear/Sad/Anger/Show/Relax/Alert`
八条 617~648 只都有,`Fight_CallOut` 612/644),正好覆盖 `RUNTIME_CLIPS` 里所有有配音的动作。

**它们不是同一段音频的两份拷贝**,这是量过的:同名事件解出的 wem 逐对比 10ms RMS 包络,
相关只有 0.11~0.42,而「同一段」的判据是 0.87 以上(rocom-capture/docs/audio.md §10)。
动作那层明显更轻(RMS 约 0.015 比叫声的 0.045)、也更长(尾巴多 0.2~0.7 秒),
听感上是垫在叫声底下的一层。

**动作音效不变调**,同样是数出来的:621 个 `Pet_Vo_*` 里 **619 个**挂着 `Pet_Vo_Pitch`
的 RTPC 曲线,而 650 个 `Pet_Action_*` 里**只有 1 个**有。那个 Game Parameter 是给嗓子的,
把它套到脚步声上是错的。

顺手量掉的一个念头:每段 wem 末尾都挂着 0.6~1.5 秒的数字静音(占时长三成,尾部
6 万个样本里只有几百个非零),看着像白占地方 —— 实测裁掉只省 **1~5%** 字节,
vorbis 编静音本来就几乎不花钱。**没做**,省得多一个会误伤的处理步骤。

### 声音的键改成动作逻辑名(2026-08-09)

原来 manifest 里 `[forms.voice]` 的键是另起的四个触发点名(`happy`/`shock`/`callout`/
`relax`),运行时靠一个 `VoiceKind` 枚举把「什么时候叫」翻成键。加到九种情绪之后这张
对照表就纯属重复了 —— 现在两节音频与 `[forms.clips]` **同一把键**(`Happy`/`CallOut`…),
于是「播哪段动作」直接决定「出什么声」,枚举与翻译层一起删掉。

还有一个连带的好处:降级也统一了。没有 `Shock` 只有 `Alert` 的形态,动作退到 Alert
(`stage::fallbacks`),现在声音**走同一张表**跟着退 —— 两边各退各的会出现「做着警觉的
动作、叫着受惊的声」。导出器那侧原来也有一张自己的降级表(取不到 `Common_Happy` 就退
`Common_Show`),按上面的覆盖率数字它一次都没生效过,一并删了。

**换键要给旧包留一手**。下载站上发出去的 `.rkpet` 是旧键(小写),换完之后新运行时查
`Happy` 会一个都查不到 —— 而结果是**不报错、也没声音**,是最难查的那种坏法。
所以 `pick_sound` 最后退一步查小写:旧那四个键正好都是动作名的小写形式,旧包照常出声。

### 头像图标要过 MODEL_CONF,不是按 conf_id 命名(2026-08-09,当天订正)

先前记的是「`Icon/HeadIcon/<conf_id>.png`,按 id 直接对上」。**那是巧合**:607 个形态里
547 个的图标文件名恰好等于 conf_id,于是错的那批一直没露头,直到有人报「苞米仔没有头像,
而炮米花顶着苞米仔的脸」。

真正的链路是 `PETBASE_CONF[conf_id].model_conf → MODEL_CONF[…].icon`:

- 苞米仔 3759 的图标是 `3760`、炮米花 3760 的是 `3761` —— 整族错开一位。按 id 找的结果
  正是那份报告:3759 没有文件(空着),3760 有文件但画的是**它前一阶**。
- 王者形态整批落在 4xxx(风暴战犬是 `4078_1`),按 id 找一个都对不上;顺带,
  收图标时按 `stem.isdigit()` 过滤会把这类带后缀的整批丢掉。
- 命中率 **包 196→197 / 201、形态 573→599 / 607**,其中 27 个原本顶着别人的脸。

**一张图标被多条配置共用是常态**,同一只的外观变体本来就共用一张(板板壳「蜕皮时的样子」
指着 3055、石肤蜥「球球尾巴的样子」指着 3106),拼图时只拼一次。但**跨包共用是配置抄漏了**
—— `000-若叶蜥`/`000-荆棘笼` 指着鸭吉吉,`000-守护者` 指着真·落陨星兔,这 6 条不认,
退回文字头像。

**别想着靠规则识别「抄来的行」**:按「名字与头像都属于另一只」去筛,全表 1136 行命中 88 条,
其中绝大多数合法(王者形态与它的战斗形态共用图标、圣代甜甜那八种外观互相错位)。所以
`Mac_LuoDaXie1_001` 那行只能人工特判(见下)。

### `Mac_LuoDaXie1_001` 的名字是抄来的,记作「守护者」(2026-08-09)

### 网页画布一定是不透明的(2026-08-09)

`wgpu` 的 WebGPU 后端只报 `alpha_modes = [Opaque]`(实测 Chromium 151,尽管 WebGPU 规范里
有 `premultiplied`)。所以预览的清屏色得自己给:前端把弹窗那块的 CSS 背景色算出来传进 wasm,
深浅主题都对得上。

算颜色**不能拿正则抠数字**:Tailwind v4 的调色板是 `oklch()`,`getComputedStyle` 就原样回
`oklch(0.21 0.006 286 / 0.4)`,按 `rgb()` 读出来是 0.21/255 —— 画出来近乎纯黑(踩过)。
让 2D 画布替我们解析,什么语法都认。

### 黑猫巫师身体偏短、尾巴笔直:动画借到了**另一副骨架**(2026-08-11)

实机截图反馈:黑猫巫师(`Com_HeiMao2_001`)「身体偏短,尾巴笔直」。渲出来比截图更狠 ——
整只揉成一团,四条腿并成两根签子,扫帚与翅膀直挺挺地插在身上。

**根因一句话:它自己没有 `Animation/`,而借用顺序把它送到了小黑猫那儿。**
按族名找同族(`heimao`)时优先同阶段,而族里只有一阶小黑猫和四阶黑猫密探,谁都不同阶,
于是先枚举到谁算谁 —— 枚举到了小黑猫。**但黑猫巫师的网格挂的骨架是
`SK_Com_HeiMaoBo_001_Skin`(92 根,黑猫密探那份)**,小黑猫是
`SK_Com_HeiMao1_001_Skin`(39 根)。

两副骨架**名字对得上一半**,这正是最坏的情况,两个症状各出自一半:

| 症状 | 出自 |
| --- | --- |
| **尾巴/帽子/翅膀笔直** | 92 根里只有 **27 根**对得上名字。巫师的两条尾巴叫 `Bone_M_1_Tail_*`/`Bone_M_2_Tail_*`、帽子 `Bone_M_Hat_*`、翅膀 `Bone_*_Chibang_*`,小黑猫只有 `Bone_M_Tail_00..05` —— 对不上的 65 根**全程停在绑定姿势**,而美术的绑定姿势本来就是摊平的 |
| **身体偏短** | 对得上的那 27 根把**小黑猫的骨骼长度**当平移写了进去。`GetBoneTransform` 在轨道没有平移数据时回填的是**动画那副骨架**的参考姿势,而 `WriteTranslation` 只拿它和本形态的绑定姿势比、不等就写一个关键帧 |

量出来的证据(glb 里 Idle 的平移首帧,单位米):24 根骨骼的平移**逐位等于小黑猫的绑定姿势**
(距离 0.00000),而距黑猫巫师自己的绑定姿势最远差 0.178。整条脊椎与四肢缩到约三分之一:

| 骨骼 | 黑猫巫师绑定姿势 | 写进 glb 的 | 小黑猫绑定姿势 |
| --- | --- | --- | --- |
| `Bip001-Spine` | 0.0517 | 0.0179 | 0.0179 |
| `Bip001-Spine1` | 0.1089 | 0.0387 | 0.0387 |
| `Bip001-L-Calf` | 0.1328 | 0.0444 | 0.0444 |
| `Bip001-L-Foot` | 0.1538 | 0.0349 | 0.0349 |

**代码里那句注释是错的,一并撤掉**:「骨架不匹配时 GlbBuilder 会按骨骼名对不上直接跳过
那段动画,所以借错了只会少动作,不会渲出鬼东西」。`Bip001-*` 是通用 biped 命名,**全库的猫
狗鸟鱼都叫这个**,所以跨骨架借用几乎总能对上一半、从不触发「一根都对不上就跳过」那条。

**改法① 借用顺序最前面加一档「骨架所属的那个资产」。** 网格的 `USkeleton` 软引用路径
(`…/Pets/Com_HeiMaoBo_001/SK_Com_HeiMaoBo_001_Skin`)**直接点名了该借谁**,读路径不加载资产。
同一份骨架 ⇒ 骨骼名与参考姿势逐根一致 ⇒ 动画原样套上、一根不漏。顺序变成
**骨架所属资产 > 同 `anim_conf` > 同族**。

**改法② `GlbBuilder` 认出「这段动画不属于本网格的骨架」就把平移重定基**:写进 glb 的是
「本形态绑定姿势 + 动画相对源参考姿势的位移」(UE 的 `AnimationRelative`)。骨架相同时
差值恒为 0、逐位等价于照抄,所以**只在借用时生效,不动其余六百多个形态**。这是兜底,不是主修 ——
单独验过(强制走同族那条旧路):平移通道 24 条 → 6 条、首帧全部落回本形态的绑定姿势,
身体比例不再被揉坏,但**姿势照样不好看**(27/92 根有轨道),所以报告里也照直写出这个比例。

**换版对照(全库重导,201 条链)**:

- **105 个借用来源全部变成「同一份骨架」,跨骨架的一个都不剩** —— 改法②在当前这版 pak 上
  一次都没触发,它是给以后的版本兜底的。
- **10 个王者形态回到包里,全库 607 → 617 个形态**(包数不变,仍是 201)。它们原来一档都
  借不到、按「零动作不出包」被丢掉(Phase 4 里「约三分之一的 `…Bo_001` 没有 `Animation/`」
  那条),而**它们的骨架就挂在自己三阶那儿**:叶冕魔力猫、圣水守护、霜翼领主、奇丽果、
  蹦蹦果、千棘海针、神谕鲨、祭礼巨像、恶魔狼王、雪影冰灵。当时记的「这批形态没做动画」
  是错的 —— 动画一直都在,只是不在它们自己的目录下。
- 真正借错了骨架(而不只是换个说法)的有十来只,最离谱的两条:**加油蟹(单只海葵的样子)
  按 `anim_conf` 借了鸭吉吉的动画**,**梦想三三(170cm)借了逗逗(38cm)**。
  古齿帝牙 / 卷发巨獭 / 琉璃君主三只王者形态都借了阿米亚特王者版,现在各归各家。
- 动作数变动只有 8 个形态、都是 ±3 段 Sleep:古齿帝牙、加油蟹变体各少 3 段(新来源自己
  就没有),晶石蜗五个变体与棋骑士(黑子)各多 3 段。**换对了骨架比多三段睡觉动作重要。**
- `cmp_shots.py` 逐项复量黑猫巫师那张:亮度 2.59 → **1.06**、调色板 0.345 → **0.027**、

### 上游 ACL 解码把轨道接错了骨骼:三条修正与一个哨兵(2026-08-11)

这三条是在 NPC 分支上查出来的(那边中招的形态多、症状大),但**判据里没有任何 NPC 特有的
东西**,宠物库照样命中,所以单独并进来。全库 201 个包 / 617 个形态重导逐字节比:
**614 个逐字节不变**,变的 3 个逐张渲图看过、都是改好。

**① 轨道映射被读成恒等,而那在数上不可能(`BorrowTrackMap`)。**

`TrackToSkeletonMapTable` 是「第 i 条轨道属于哪根骨骼」的权威答案。压缩器会把整段恒定的
骨骼(道具、末端 Nub)整条剔掉,于是轨道数少于骨骼数、映射非恒等 —— 这种 CUE4Parse
处理得**是对的**。坏的是另一种:**轨道数少于骨骼数,映射却是恒等的**。恒等 =
「剔掉的是末尾那几根」,而末尾那几根往往是整条小腿。

同一个资产里别的动作带着一份**真映射**,直接借过来用,按**轨道数**配对
(同一个资产不同动作剔掉的根数不一样,而同一个轨道数下的映射逐条相同);
同一个键下两段不一致就整条作废。宠物库里权杖-Ⅱ(`Mac_QuanZhangll2_001`)命中这条。

顺带删掉一行老代码:`if (FindTrackForBoneIndex(bone) < 0) continue;` —— 轨道表比骨骼少几条时
它对**末尾那几根恒返回 -1**,那几根会被整段丢掉(渲出来僵在绑定姿势)。

**② 借不到真映射时的推断(`DetectTrackShift`)。**

从后往前找「平移恰好等于后面第 k 根的**参考姿势**」的骨骼,要求整批一致(至少 3 根
**能判别**的,中间允许 3 根说不清的 —— 错位区间里也有本来就在动的骨骼)。
这条推断**事后被①独立验证过**:同一个资产上,推出来的起点与位数与资产自带的真映射
一模一样。宠物库里瞌睡王与钨丝贝贝命中这条(各错 1 位)。

**③ 缩放那一路不跟着错位走。**

ACL 把旋转/平移/缩放分三份存,三份**各自**把「整段恒定」的轨道剔掉。道具骨的旋转平移恒定
(被剔了)而缩放不是(游戏靠把它缩到 0.1 来藏道具),于是缩放那份没被压缩、下标仍然对着
骨骼序。所以错位的动作里 **旋转平移读错位后的轨道、缩放读本骨骼那一格** ——
跟着错位读会把道具的「藏起来」缩放扣到小腿上,整只脚缩进裤腿。
还要把「没有旋转平移轨道、但缩放那一格有数据」的骨骼留下(原来一律跳过),
否则该藏起来的道具会一直挂在身上。

**④ 兜底哨兵:有肉的骨骼被「恒定地」挪出绑定姿势(只报不改)。**

恒定 = 这段动画根本没在移动它,那这个偏移就不是动作,而是「动画里记的骨骼位置和这个网格
的不一样」—— 照抄过来就是那块肉被拉飞。门槛 10cm,且只算**真有顶点权重挂着**的骨骼
(定位骨写歪了也看不见)。**只报不改**:单看「恒定偏移」判不出对错(坐下时根骨骼恒定压低
半米那是对的),报出来让人去渲一张看看,好过悄悄猜错。上面那三条改完之后,它就是
「还有没有漏网的」那道网。

**顺带修好的**:`--probe-anim` 原来用**网格**的骨骼序去查轨道,而轨道是按**骨架**的骨骼序
排的。两者顺序可以不一样,于是探针报出来的 Δ 是「这根骨骼」对上「另一根骨骼的轨道」——
一个会把排查引到沟里的错。现在改用骨架序,并额外打三行:网格与骨架的参考姿势差几根、
轨道映射是不是恒等(**非恒等就是上面①的信号**)、以及 `--probe-anim <资产>:<动作>`
把那一段逐根骨骼摊开(轨道号 / 参考姿势 / 首帧平移与旋转)。
